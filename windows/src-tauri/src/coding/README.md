# Coding native contracts

All coding actions are explicit local evidence operations. No account balance is treated as Codex quota; no native command approves permissions or changes Codex configuration.

- `coding_history_snapshot/save/clear`: opt-in `%LOCALAPPDATA%\com.roadeep.desktop\coding-history-v1.json`, version 1 envelope, at most 512 events/2 MiB/7 days. Snapshot/save and hourly app maintenance prune expired records. A process-local generation revision invalidates saves across clear and retention transitions. A mutex serializes background filesystem work, including preference persistence. Windows replacement uses a synced, unique adjacent temporary file and atomic `MoveFileExW`. Corrupt/unsupported envelopes produce `history-invalid` and remain until explicit clear. Disabled snapshots never read retained content.
- History keeps provider/session identifiers, generic titles, bounded redacted paths/tool labels, tool completion/exit status, context/quota and validated small test counters. It strips commands, outputs, patches and original prompt titles. Restoration is archived frontend evidence with unknown test freshness.
- `coding_git_inspect`: requires an existing absolute local drive directory. Git resolves from absolute PATH entries; inherited `GIT_*` overrides are removed. Optional index locks, pager, hooks, fsmonitor, submodule recursion, external diff/textconv, configured clean/smudge/process filters, prompts and protocols are disabled. It returns status plus separately labeled staged and unstaged patches (also unborn repositories); untracked contents are never read into patches. Each Git process starts suspended, enters a one-process Windows Job, then resumes; even concurrent config changes cannot execute a helper, and cancellation closes the Job. Two concurrent inspections maximum; total process deadline 10 seconds; each stdout bounded to 1 MiB and stderr to 8 KiB; at most 500 files/64 KiB redacted UTF-8 patch. Working-tree evidence has no per-session authorship or correctness guarantee. Unsafe filter configuration fails visibly.
- `coding_handoff_agents/handoff`: discovers only codex/claude/gemini `.exe` or `.cmd` launchers on absolute PATH entries. Handoff writes a generated redacted 128 KiB note and opens a visible system `cmd.exe` console using fixed allowlisted arguments. Shell expansion/control characters in executable and generated note paths are refused. Evidence is never interpolated into shell syntax. Return success confirms only terminal creation. Launch failure removes its note; no agent launch occurs in tests.

Safe errors are stable codes and logs omit raw evidence, paths and tool output. Tests use generated temporary files/repositories, in-memory bounded streams and a mock launcher. Run `cargo test -p roadeep coding:: --lib` from `windows/`.

## Desktop live observation

The opt-in observer recognizes desktop task_started as a new turn, alongside legacy user_message; private rich UserMessage bodies are ignored. Recent existing sessions recover a bounded 2 MiB tail on attach. Explicit clear retains its EOF watermark. Reads are bounded to 1 MiB per session/poll and complete records to 2 MiB; displayed output remains 6,000 redacted characters. The latest 16 rollouts are selected. Current UTC date ± one day is checked every three seconds; older date folders are rediscovered every 30 seconds, capped at four years and 8,192 file entries. Resumed sessions can remain in their old date folder. No transcript is executed and no Codex configuration is modified.

Read-only actual-session verification prints aggregate counts only. Set ROADEEP_CODEX_TEST_ROOT to the absolute sessions directory, optionally ROADEEP_CODEX_TEST_SESSION to the expected session ID, then run cargo test --lib coding::tests::observe_actual_desktop_sessions_without_content_output -- --ignored --nocapture.
