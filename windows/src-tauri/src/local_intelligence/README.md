# Local intelligence and speech

The app owns verified engine paths through `local_runtime`. No host executable, URL, model path or command is accepted from a webview. Engines are loaded on demand and exit after one bounded operation; the app retains no model in idle RAM. No inference, transcription, audio or conversation content is logged or sent to an external service by this module.

`local_brain_chat` accepts one user message and at most twelve bounded user/assistant messages. Its deterministic policy delegates tool actions, coding, current information, large requests and explicit external context to the existing Roadeep API. For small conversation, translation and rewriting, a transient llama CLI generates a constrained JSON answer. Local responses execute no tools. An invalid answer, runtime failure or timeout returns a truthful cloud route and safe error reason; the frontend chooses whether to invoke the existing API. Cancellation rejects rather than triggering a cloud handoff. Vulkan uses the GPU where supported; a failed launch has one CPU-engine retry and labels the resulting reply `local-small-task-cpu`.

`local_speech_transcribe` accepts canonical base64 containing PCM16, mono, 16kHz RIFF WAV, between 0.1 and 30 seconds. It validates RIFF lengths, chunks, encoding and signal energy before starting Whisper. Noisy inputs can still require user correction; transcription is never represented as a verified intent. `local_speech_speak` accepts at most 1,500 characters and returns validated PCM16 mono WAV from Piper. Speech never falls back to a cloud provider.

All commands require the island webview; settings installation remains in `local_runtime`. `local_brain_cancel` accepts an optional matching request ID and cancels the active speech or brain operation. A single-operation lock prevents competing models on an 8GB machine. Windows child processes start suspended, enter a kill-on-close Job Object before resuming, use an explicit verified engine directory, and have bounded stdout/stderr. Prompt text lives in a UUID workspace rather than process arguments; Piper receives text through stdin. Workspaces are deleted after success, failure or cancellation. Logs include only operation kind, validated request ID, duration and outcome.

Brain deadlines are 90 seconds per GPU/CPU attempt, transcription 90 seconds and speech synthesis 60 seconds. Stream output is capped at 128KiB per stream. Result files have independent limits. Native request IDs are at most 64 ASCII letters, digits, underscores or hyphens.

The pinned llama CLI writes a conversation transcript. Native code compares and removes the exact complete native prompt prefix before parsing a strict single generated JSON object; user-provided JSON is never taken from console output. Runtime initialization runs independently of settings, is serialized across first callers, and an installation write lock prevents replacing binaries or models while an engine uses them. Cancellation is registered before cold verification so stopping a pending operation cannot start an engine afterward.

Run native tests with `cargo test --lib local_intelligence::`. The ignored `installed_engine_canned_brain` test verifies the actual same native inference and parser using downloaded official assets in a directory explicitly selected by `ROADEEP_LOCAL_TEST_ASSETS`; its prompt is synthetic and it uses no credentials, microphone or user history.

Two further ignored tests exercise native Piper synthesis followed by 16kHz resampling and native Whisper recognition, and actual invalid-model/in-flight cancellation behavior. In synthetic verification, speech is intelligible enough for a basic Persian transcript but contains recognition mistakes; these tests do not establish human voice accuracy or natural conversational quality.

Administrator voice matching uses the pinned Sherpa CAM++ ONNX speaker model through a one-shot native child. `speaker_enrollment_begin/end`, `speaker_enroll`, and `speaker_clear` require settings; status and verification accept settings or island. Enrollment validates at least eight seconds and compares three separate segments for consistency. Verification requires at least two seconds; uncertain or different voices are rejected before transcription. A matched response issues an expiring, single-use ticket bound to the complete WAV SHA256 and current enrollment generation; global voice passes that ticket to transcription. Clearing or reenrolling invalidates prior tickets. The compact quantized reference embedding is stored only in a dedicated Windows Credential Manager entry; raw enrollment audio is never persisted.

This matching is probabilistic voice filtering, not authentication or replay detection. The conservative threshold is based on consistency and limited public fixture verification, not broad real-world accuracy. The native helper runs CPU with two threads and a twenty-second deadline, inherits existing bounded Job cancellation, and starts before Tauri initialization. It loads only the verified isolated DLL directory. Settings enrollment pauses global voice; request cancellation prevents late enrollment writes. The ignored `actual_speaker_subprocess_matches_heldout_and_rejects_other` test needs explicit `ROADEEP_SPEAKER_TEST_EXE` and `ROADEEP_LOCAL_TEST_ASSETS`; it uses public held-out/different-speaker WAVs and an in-memory profile, never the administrator credential.

Speaker references are saved with Credential Manager raw-secret bytes, rather than UTF-16 password encoding: the 512-dimensional compact JSON fits the 2560-byte Windows credential blob cap. Read-only loading recognizes old bounded UTF-16 JSON references without rewriting them. The ignored isolated credential roundtrip test uses a fresh UUID service and synthetic embedding, cleans it up, and never accesses the administrator profile.

Enrollment trims only quiet leading/trailing20ms energy frames, with100ms retained context, before dividing into three independent spans. Internal pauses remain; each trimmed span needs two seconds. The existing0.55 consistency floor and speaker-match thresholds are unchanged. Public same-speaker audio plus three trailing seconds originally failed consistency0.5006; the bounded trim fixture passes0.8784. This is a synthetic regression for boundary-pause handling, not an accuracy claim for arbitrary human recordings. Enrollment logs allowlisted failure codes only, never audio, vectors or free-form error text.

## Voice analysis and local confirmation

`adminVoiceMode` defaults to manual. Saved invalid values fall back to manual, while settings updates reject unknown modes. `voice_assistant_analyze` uses the same pinned, bounded, cancellable small model and strict generated-output isolation. It classifies only task/note summaries; it cannot execute commands. Always-mode unrelated remarks stay silent. Fixed desktop intents route directly to the fixed launcher.

There is one in-memory task/note proposal for five minutes. Exact contextual yes/no applies only to that pending proposal; explicit UI confirmation uses its UUID. Only reviewed task title or note text is saved through the existing transactional planner. Extra scheduling/hidden arguments are refused on the voice tool path. Failed storage retains the proposal for retry, concurrent confirmations save once, and a clear/runtime-disable/profile-removal generation rejects stale model/tool proposals. No raw audio, utterance logs, or biometric data enter proposals.

Voice cloud turns have isolated standard-model threads, no selected custom agent, no file uploads or arbitrary external MCP/computer tools. They offer the ten built-in planner tools plus the fixed desktop tool. Task/note tools create proposals, never immediately save; their confirmation question ends the loop without a further model reply. Server approvals are cancelled and refused, while typed approvals remain explicit clicks. API search/reasoning options remain configured read-only capabilities.

`actual_voice_intent_model` is an ignored synthetic Persian model smoke requiring `ROADEEP_LOCAL_TEST_ASSETS`; it never writes a user planner. `desktop_actions::tests::actual_this_pc_launch` additionally requires `ROADEEP_TEST_DESKTOP_LAUNCH=1` and explicitly opens only This PC. Ordinary tests mock the launcher and planner saver.
