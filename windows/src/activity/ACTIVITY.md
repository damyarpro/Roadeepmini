# Local coding evidence model

Fresh TypeScript implementation; no third-party code or new dependencies. `ActivityStore` validates and redacts wire events before retaining at most 16 sessions, 160 events per session, 60 file paths per event, and 12,000 characters of patch/output. `Activity` is the shared instance. `ingest(unknown)` returns whether accepted, `sessions()` provides defensive newest-first snapshots, `subscribe(listener)` returns an unsubscribe function, and `clear()` erases retained evidence. No persistence, execution, network calls or automatic approvals occur here.

`CodingEvent` is the camelCase backend contract in types.ts. Starts and results pair only by session + call ID; timestamps order replay. Missing command/output/status remains unknown. `ActivitySession` contains retained events, observed changed files, compact last patch, latest test evidence, status, counts and advisory overlaps. Relative file paths need an observed root before cross-session comparison; Windows paths are normalized case-insensitively. A reported overlap does not establish simultaneous writes, ownership or a file lock. Finished sessions do not produce overlap warnings.

Tests require an observed successful exit plus a nonzero reported executed count. Failed exits or reported test failures take precedence. Truncated, missing, zero-test and watch-mode output cannot establish success. Freshness compares the test start with the latest observed mutation, including edits while tests run. The parser recognizes common Rust, pytest, Node and JS runner summaries; unsupported runners are unknown. No semantic correctness claim follows from a passing test.

`diffPreview` emits bounded plain-text lines; the renderer must use textContent. `recapMarkdown` escapes untrusted Markdown and includes evidence identifiers, failure operations, test freshness and a portable checklist. It does not include arbitrary full command outputs or prompts. Redaction is best effort for recognizable keys, credentials and private-key blocks; it cannot identify every sensitive business value. Never treat exports as automatically safe to publish.

Run meaningful fabricated-fixture tests with `npx vitest run src/activity/store.test.ts`. They cover hostile inputs, bounds, secret patterns, snapshot dedupe, call pairing, out-of-order replay, edit freshness, unknown Claude output, advisory Windows overlaps, Markdown injection and parser edge cases.

Each observed prompt starts a new evidence turn; older request files, failures and tests do not carry forward. In-flight or unknown-result mutations make freshness unknown. Failed patches are unconfirmed. Codex changes require exit zero or explicit patch success; Claude PostToolUse supplies a successful tool observation, without implying a process exit or Git validation. Freshness is against observed changes only; shell writes may be unseen. Markdown export accepts optional language fa/en.

## Optional retained history and coding tools

`retainCodingHistory` defaults to false. `toggleHistory()` changes the native preference with visible failure state in `Monitor.history`. Startup restores a versioned native snapshot as archived evidence; restored sessions never claim a running turn or overlapping writes. Saves coalesce within 500 ms of the first change and serialize; cancellation epochs discard late restores and native revisions reject writes after clear/disable. Clear erases in-memory and native retained history; disabling retention removes archives. Observation off preserves retained evidence while retention remains enabled.

History is bounded to seven days, 512 events and 2 MiB, with no titles/prompts, command output, command strings or patches. Normalized historical test counts retain their original verdict but always have unknown freshness. Context/quota fields use observed counters only; usage events never reset a turn or reopen finished sessions. Invalid/nonfinite values are discarded, and context counters exceeding the observed window are rejected.

`Bridge.codingGitInspect(cwd)` is an explicit read-only whole-working-tree inspection, independent of session attribution. `codingHandoffAgents()` discovers allowed local CLIs and `codingHandoff(cwd, agent, content)` launches only from an explicit UI action. A successful handoff confirms terminal launch, not task execution or correctness. The native implementation validates roots and bounds process output. No polling or implicit Git/handoff invocation is added by the model layer.

Codex observation also feeds the compact island through island-adapter.ts. A dedicated Codex task aggregates live sessions; an active parent outranks a finished worker. Existing chat/approval/selected-agent focus and active Claude hooks remain respected. Idle default focus follows Codex thinking/working/error/finished evidence. Archived quota-only and stale sessions do not animate as active work. This display adapter has no execution or approval capabilities.
