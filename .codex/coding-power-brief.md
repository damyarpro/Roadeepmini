## Shared contracts

Existing CodingEvent gains optional `context: {usedTokens?:number,limitTokens?:number,usedPercent?:number,model?:string}` and `usage: {primary?:{usedPercent:number,resetsAt?:number,windowMinutes?:number},secondary?:same}`; kind additionally `usage`. All number fields finite/nonnegative and bounded; percentages 0..100; timestamps UTC epoch ms. Do not infer quotas/context from account balance. Codex context is `last_token_usage.input_tokens / model_context_window`; cumulative totals are not current context. Usage-only events must not reopen a finished session or reset a turn.

Settings adds `retainCodingHistory:boolean` default false. History is normalized/redacted structural local evidence, max7days,512events,2MiB; no raw transcript, prompt, command, output or patch retention. Explicit UI opt-in states persistence and location, disabling erases retained file and clears archived evidence. Clear evidence erases both memory and saved history. Saved history is a versioned bounded envelope, atomic replace, invalid/corrupt input fails safely with visible error, no raw data/path in logs. Native history state serializes writes and revisions so late saves cannot resurrect clear/disable. Restore marks sessions archived, never newly running or generating overlaps. To preserve useful test evidence without outputs, event may have `testSummary:{verdict:'passed'|'failed'|'unknown'|'skipped',passed:number,failed:number,skipped:number}` attached by frontend history serializer to its matching result event. Both boundaries validate integer counts (0..1e9), passed requires passed>0 + exitCode0, failed wins on nonzero exit/reportedfailed count. Historical summary is never current freshness: restored tests always freshness unknown until a new observed run. No synthesized output or commands. Native history whitelist retains only this structured summary and normalized metadata/context/usage/files. UI states old patches/output are not saved.

Commands:
- `coding_history_snapshot() -> {revision:number,events:unknown[]}`; only reads when enabled.
- `coding_history_save(events:unknown[],revision:number) -> boolean` (false stale revision; error invalid/write failure).
- `coding_history_clear() -> {revision:number,events:[]}`; bump revision and delete persistent file, keeps preference.
- existing `coding_clear` also clears native history; disabled observation does not silently erase retained history while retention is enabled.
- `coding_git_inspect(cwd:string) -> GitInspection` explicit user request only, no poll or automatic git writes.
- `coding_handoff_agents() -> {id:'codex'|'claude'|'gemini',name:string,executable:string}[]` from absolute PATH entries; never search project cwd.
- `coding_handoff(cwd:string,agent:string,content:string) -> {path:string,agent:string}` saves bounded redacted note then starts a visible interactive terminal only after explicit user click. Fixed allowlisted programs/args, no arbitrary commands. Windows .cmd quoting must reject characters that cannot be kept literal, no shell interpolation of evidence. Spawn only confirms terminal launch, not task continuation. No file/config changes except explicit handoff note.

`GitInspection {root:string,head?:string,at:number,files:{path:string,status:string}[],patch:string,truncated:boolean}`. Return whole current working-tree evidence, not attribution to one session. Read-only git status+diff, no checkpoints/restores. Validate absolute existing local cwd, reject network UNC paths/NUL/control chars; do not execute git from cwd. Bounded file count500, patch64KiB, output cap, process timeout10s and concurrency cap. Disable external diff/textconv/hooks/fsmonitor/pager/submodule recursion and optional index locks. Git reads are not verified code correctness; untracked file contents are not synthesized into diff. Redact output before frontend. Safe error codes and logs. Test fixtures use temporary repositories, no personal checkout edits.
