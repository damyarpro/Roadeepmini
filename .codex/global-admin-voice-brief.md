# Global admin voice implementation brief
Latest user wants one small voice toggle on the home page, enabled voice across all app views, accepts only enrolled admin speaker, replies/actions via existing local-small/cloud-complex chat route. Voice enrollment/settings live in Settings. Complete prior full offline installer objective including speaker model/runtime.

Ownership: global_voice_ui owns windows/src/local/**, windows/src/core/bridge-local.ts, frontend main/island/home/chat integration, assistant-controls default local voice UX, settings/assistant-settings.{ts,css,test.ts}, necessary preview/mock/test files. Native local_engine owns local_runtime/**, local_intelligence/** and native registration only. local_assets owns bundled assets/staging/pack/resource config/docs. Do not revert other edits; coordinate contracts before edits. Root reviews independently and final gates/UI critic loops. No real user mic recording or paid API during development tests.

Architecture: one global microphone controller in island webview, not mounted inside chat. Toggle explicit opt-in persists across navigation, with visible state/accessible stop. If no admin voice, first click opens settings without recording. Settings explicit enrollment records locally, validates quality and stores only native embedding/config; clearing profile stops global mic. Settings enrollment must pause island listening via native cross-window events. Speaker verification happens BEFORE transcription or any API dispatch, rejects uncertain/other voice, never fakes identification from text/energy. Native speaker APIs pending exact contract from native worker/root: status, enroll(wavBase64), verify(wavBase64), clear. All WAV 16k mono PCM16 and bounded <=30s; request IDs/cancellation guards as existing.

Continuous recording uses bounded VAD utterance segmentation with pre-roll, minimum voiced duration and silence endpoint; one operation at a time, bounded buffers/no unbounded queue, no processing silence. Pause capture while generating/playback to avoid echo; re-arm after completion. Late promises cannot revive disabled/cleared mic. Audio release on app shutdown/disable/runtime disabled, not view navigation or hide when toggle enabled. Existing explicit remote voice remains advanced; existing approvals/actions unchanged, biometric match is not permission approval. Chat voice dispatch must work from all views and show answer in chat when needed; preserve selected cloud model, route local small tasks even if signed out, maintain provenance and language.

UI: remove large default turn-based panel as main voice entry. Home compact microphone button 44px touch area; active indicator usable elsewhere. Settings admin enrollment/re-record/delete and runtime setup truthful progress/errors. Preserve current design tokens, Persian RTL, keyboard labels/focus, no technical model/control clutter in home. Read architecture and explain before major edits. Tests: navigation does not stop enabled controller, unknown speaker never transcribes/routes, uncertain rejected, profile missing, cleared/disable cancels, async stale mic races, silence/max duration, TTS echo suppression, local/API response routing, settings enrollment no raw persistence. Fresh UI self-review loop 3-6 iterations after stable implementation.
