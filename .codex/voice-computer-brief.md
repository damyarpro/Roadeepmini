# Voice and isolated computer implementation

User explicitly requests both real voice conversation connected to existing chat/tools and dedicated isolated agent computer. No fake runtime. Current Tauri Rust/vanilla TypeScript app; preserve existing identity, chat/model/history/approval behavior and tokens. Workers are not alone: do not revert others' changes. No API keys/personal transcripts in tools/logs. No installation/large downloads without need; no silently configured service calls. Full provider calls require user configured key; test mocks otherwise. Root orchestrates and audits, final checks personally.

Ownership:
- voice_backend: windows/src-tauri/src/voice/** only, windows/src/voice/** only, voice documentation/tests in own directories. Module owns CredentialManager key and validated local config without editing secrets/settings globally.
- computer_backend: windows/src-tauri/src/computer/**, windows/computer-runtime/**, windows/src-tauri/src/roadeep/chat.rs for tool integration only. No lib.rs edits. Own tests/docs in these modules.
- integration_ui: windows/src/core/bridge-assistant.ts new dedicated bridge/types, windows/src/views/chat.ts, new windows/src/views/assistant-controls/**, windows/src/settings/main.ts plus new assistant settings module/css/locales, windows/src-tauri/src/lib.rs for all module/state/command registration and shutdown. Coordinate names with backends; no edits to their module internals. Add previews and meaningful UI tests. Can add small methods to Bridge only if needed; prefer dedicated bridge.

Architecture contract:
Voice: OpenAI Realtime GA unified WebRTC POST https://api.openai.com/v1/realtime/calls, Rust sends SDP+server-owned session multipart using credential stored Windows CredentialManager, never token to frontend. User-selectable model/voice with conservative validated defaults (gpt-realtime-2.1/marin documented official). Voice settings loaded from dedicated local config (no secret); start only click, singleton lifecycle, max15min, mute/unmute/end, cleanup peer/channel/media on hidden chat/signout/navigation/rebuild/errors. Function ask_roadeep with query string delegates to SAME chat submit/Bridge.chatSend and usual tool approvals, exact once call_id dedupe bounded; no parallel independent bypass tool runner. Existing history context bounded, captions live; no persistent audio. Output muted while waiting tool approval if necessary. Restrict function contract and user-visible error/cancel states. New text/user action or model/agent/thread switch should end voice or disable while active. Native voice end cancels in-flight initialization/hangups; no secrets logging. Mock lifecycle/security/event tests required.

Computer: real local Docker runtime, one isolated container per validated agent identity, no user host filesystem mount/Docker socket. Local image roadeep-computer:1 explicitly built from checked-in runtime. Default unavailable unless Docker daemon+image ready; visible actionable setup. No auto-pull/build in UI. Non-root, read-only rootfs, /workspace isolated volume/tmpfs, cap-drop/no-new-privileges, CPU/memory/PID limits, no published ports. Docker via arg arrays, bounded process/output/deadline with process-tree cleanup existing native patterns. Agent operations browser navigate/screenshot/click/type/key/scroll, relative text files list/read/write, terminal command. Metadata/status bounded; snapshot return image not giant tool text. Host commands never accessible. Singleton per-agent operation lock, isolation/ownership checked server-side, explicit lifecycle start/pause/resume/stop/reset status. UI refresh only visible; human takeover pauses agent operations. All side effects exposed to existing local chat approval flow (Ask), status/list/read may Auto conservatively. No background computer activity unless started explicitly; no app startup creates containers. Runtime unreachable/ownership errors visible, no fake success. No destructive host action. Tests validate args/isolation/path/ownership/approval dispatch. Runtime validates URL and file paths; no secrets in logs.

Native planned commands (camelCase wire):
voice_status -> {configured:boolean,model:string,voice:string}; voice_configure(model,voice,apiKey?:string) -> status; voice_clear_key; voice_start(sdp:string) -> {id:string,sdp:string}; voice_end(id?:string).
computer_status(agentId:string) -> {available:boolean,state:string,agentId:string,error?:string}; computer_start/pause/resume/stop/reset(agentId:string) -> status; computer_takeover(agentId:string,on:boolean) -> status; computer_operate(agentId:string,operation:object) -> result (explicit UI operation).
Module-native signatures/state may refine with agent coordination. UI worker must establish shared types/signatures before consuming. Chat tool dispatch gets agent identity internally from options; model cannot choose another agent/container. Computer module operations for agent refuse takeover/paused/stopped. Tool names namespace computer__*. Lifecycle user controls separate from model operations. Existing ToolFlags/use_tools enforce chip; no bypass approvals.

Design: compact dark island, existing sky accent/Vazirmatn/radii/spacing. Two restrained controls Voice and Computer in chat, expandable status panel with one clear primary action, visible missing-key/Docker/image instructions, localized Persian+English, no implementation noise in main flow. Settings advanced setup may show precise Docker command. Screenshot previews fixture-only explicitly mark preview and never pretend native provider succeeded. Min3 fresh ui-critic rounds; root owns capturing/review. No large browser downloads.

Final success: typecheck + TS/native meaningful tests, compiled Windows build, live preview controls and no hidden timers/media, verified tool approval dispatch remains exact. Report limitations for real API/microphone/Docker unavailable; no fabricated real-service success.
